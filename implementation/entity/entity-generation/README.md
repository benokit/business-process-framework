# entity-generation

An entity that generates entities of other types, and acts back on its source through an interface only the generated entity can use. It is built on [trait entries and messages](../entities/README.md#messages-between-traits); the design and its reasoning are in [generators](../../../design/generators.md). [entity-amendments](../entity-amendments/README.md) is the special case of an entity with a versioned body that is amended.

- **`generator`** (trait, key `generator`; the kind `generator-trait`, whose subkind `plain-generator-trait` is the default): the entity type's declarations, `{ declarations: { <name>: { type, open?, input?, effects? } } }`.
  - `type`: the entity type to generate; it has the trait `generated`.
  - `open`: maps `{ entity, input }` (the source as its type reads it, and the `input` of the request) to the initial traits of the new entity, `{ body: … }`; without it the body is the `input`.
  - `input`: the id of a schema that checks the `input` of the request.
  - `effects`: named lists of trait operations `{ key, operation, input }` on the source, whose `input` maps `{ source, generated, link }` (the source as its type reads it, the generated entity as stored, its link). The name of an effect is the message the generated entity sends.
  - Declarations are contributed like any trait use: in the `traits` of the entity type, or by fills of the slot `traits` that name only the key (`{ key: "generator", configuration: { declarations: { … } } }`; any number of them on one target, united).
- **the operation `generate`** of `generating-entity-type` (`generate({ businessKey, generator, key?, input?, context? })` on the source, which `starts` the process `generate` of the trait; `entity-generation-gateway.generate` takes the entity type as well, for a route that names it): in one transaction it finds the declaration (`invalid` otherwise), checks `input`, makes the traits with `open`, asks the kind of the trait for `admit` (the key and the revision of the source for the link; the plain generator takes the key from the request) and creates the entity with its link. The state model of the source lists the states it may start in as `generate`; authorization names the action. The operation `preview` (`{ businessKey, generatedType, generated, effect }`) returns the commands an effect would write, writing nothing.
- **`generated`** (trait, valued): the link `{ sourceType, sourceKey, sourceRevision, generator, context }`, fixed at creation (the trait has no operation that writes it), and the bindings of the moves of the generated entity to effects, `{ <effect>: { <dimension>: { <from>: <to> } } }`. Its `guard` refuses `create` unless the creation runs in the entry `generate` of the source the link names; its `react` delivers the message named by the effect whose move the change made to the `generator` of the source.
- **`receive` of the generator** answers such a message: it reads the sender's stored record (nothing is given by the caller), refuses unless the sender names this entity in its link (`forbidden`) and is in the state the binding says (`conflict`), asks the kind for `guardEffect`, and returns the items of the effect mapped over the scope, which `deliver` writes as one change in the transaction of the move. The state model of the source gates the message as `generator/<effect>`. A message from the source itself goes to `ownMessage`.
- **the hooks of the kind**: `generator-trait` leaves `admit`, `guardEffect`, `settle` (operations added to every effect), `effectsOf` (the items of an effect, so a kind may supply defaults) and `ownMessage` to its subkinds; `plain-generator-trait` does nothing in them. Policy of a particular process is written as a subkind.
- **`validate()`** checks every declaration: `open` against the body of the generated type, the `input` of each item against the input of its trait operation (the scope typed as above), an item whose trait or operation the source hasn't, a trait used twice in a list, and the pairs the trait declares in its data (`pairs: [{ changes, undoneBy, defaultKeys }]`: an effect that changes a trait its counterpart leaves).
