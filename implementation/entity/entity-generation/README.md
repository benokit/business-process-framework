# entity-generation

An entity that generates entities of other types, and acts back on its source when the generated entity makes a move. It is built on [trait processes and writes](../entities/README.md#writes-between-traits); the design and its reasoning are in [generators](../../../design/generators.md). [entity-amendments](../entity-amendments/README.md) is the special case of an entity with a versioned body that is amended.

- **`generator`** (trait, key `generator`, the kind `generator-trait`): the entity type's declarations, `{ declarations: { <name>: { type, open?, input?, effects? } }, key?, context?, effects? }`. The trait has one operation, `generate`, and no hooks.
  - `type`: the entity type to generate; it has the trait `generated`.
  - `open`: maps `{ entity, input }` (the source as its type reads it, and the `input` of the request) to the initial traits of the new entity, `{ body: … }`; without it the body is the `input`.
  - `input`: the id of a schema that checks the `input` of the request.
  - `effects` of a declaration: named lists of trait operations `{ key, operation, input }` on the source, whose `input` maps `{ source, generated, link }` (the source as its type reads it, the generated entity, its link). The name of an effect is the one the `generated` trait binds to a move, or `generate` (below).
  - Declarations are contributed like any trait use: in the `traits` of the entity type, or by fills of the slot `traits` that name only the key (`{ key: "generator", configuration: { declarations: { … } } }`; any number of them on one target, united).
  - The three other fields are the policy of the entity type, set once by its class and common to its declarations: `key` maps `{ source, request }` to the business key of the generated entity (`#.request.key` without it), `context` is the id of a schema for the `context` of the request, and `effects` maps `{ source, generated, link, declaration, declared, effect, request }` to the operations an effect runs, `declared` being the declaration's own list with its inputs mapped (`#.declared` without it). A kind that wants a rule around every effect, such as a ledger, writes it there.
- **the operation `generate`** of `generating-entity-type` (`generate({ businessKey, generator, key?, input?, context? })` on the source, which `starts` the process `generate` of the trait; `entity-generation-gateway.generate` takes the entity type as well, for a route that names it): in one transaction it finds the declaration (`invalid` otherwise), checks `input` and `context`, makes the traits with `open`, writes the operations of the effect `generate` to the source (none unless the policy `effects` gives some), takes the business key from `key`, and creates the entity with its link, whose `sourceRevision` is the revision of the source after that write. The state model of the source lists the states it may start in as `generate`; authorization names the action.
- **`generated`** (trait, valued): the link `{ sourceType, sourceKey, sourceRevision, generator, context }`, fixed at creation (the trait has no operation that writes it), and the bindings of the moves of the generated entity to effects, `{ <effect>: { <dimension>: { <from>: <to> } } }`. Its `guard` refuses `create` unless the creation runs in the process `generate` of the source the link names. Its `react` finds the effect whose move the change made, reads the source through the link, computes the operations of the effect from the declaration (and the policy `effects`) and writes them to the source, in the transaction of the move: nothing is given by a caller, and the link names the only entity it can write. The state model of the source gates the write as `generator/<effect>`; a trait of the source sees it in its `guard` with `origin`.
- **`generated-entity-type`** (kind): declares the operation `preview({ businessKey, effect })`, which starts the process `preview` of `generated` and returns the commands an effect would write on the source, writing nothing.
- **`validate()`** checks every declaration: `open` against the body of the generated type, the `input` of each item against the input of its trait operation (the scope typed as above), an item whose trait or operation the source hasn't, a trait used twice in a list, and the pairs the trait declares in its data (`pairs: [{ changes, undoneBy, defaultKeys }]`: an effect that changes a trait its counterpart leaves).
