# entity-tasks-http

`POST /entities/:entityType/:businessKey/task/answer` with `{ outcome, result? }` → `run` of the operation `answer` of the trait `task` of the entity type ([entity-tasks](../../entity/entity-tasks/README.md)), which must have it (`invalid` otherwise) → the record, with its revision as `ETag`. `If-Match` is required, as in [entity-states-http](../entity-states-http/README.md). The answer closes nothing: the process that asked for the task does. The [operation](../../services/authorization/README.md) is `{ area: "tasks", resource: <entityType>, action: <outcome> }`, so a role may be granted `approved` and `rejected` separately, as transitions are; the outcome is the schema `task-outcome-name`, the closed set of every outcome a user may give in any task type, registered at load (an outcome no grant names is refused with `403` before its schema is checked). The actor `entity-task-worker-actor` grants the area. No route for `claim` exists yet.
